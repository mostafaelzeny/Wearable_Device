Hardware Assumption

The sketch is written for an AD5933 impedance measurement circuit. The unknown impedance is connected between VOUT and VIN. A feedback resistor is connected between RFB and VIN. This matches the AD5933 datasheet receive-stage circuit.

The datasheet states that the receive side is a current-to-voltage amplifier. The feedback resistor sets the current-to-voltage gain, and the PGA gain can be either x1 or x5.

Datasheet Measurement Flow

The AD5933 datasheet describes this basic sweep sequence:

  1. Program the start frequency, frequency increment, and number of increments.
  2. Place the AD5933 in standby mode.
  3. Issue initialize-with-start-frequency command.
  4. Wait for the circuit to settle.
  5. Issue start-frequency-sweep command.
  6. Poll the status register until valid real/imaginary data is ready.
  7. Read real and imaginary registers.
  8. Increment or repeat the frequency until the sweep is complete.

Your code mostly follows this flow in setupSweep(), waitForData(), calibrateSystem(), and measureUnknownRC().

Calibration Explanation

In calibrateSystem(), the code asks the user to connect a known 16k ohm resistor between VOUT and VIN. This known resistor is used to calculate a gain factor for each frequency point.

magnitude = sqrt(real^2 + imaginary^2)
gainFactor = (1 / calibrationResistance) / magnitude

This follows the datasheet. The AD5933 does not directly output impedance in ohms. It outputs real and imaginary DFT codes. The gain factor converts those raw codes into admittance, and the reciprocal gives impedance.

The code also stores systemPhase[i] during resistor calibration. A pure resistor should not add significant impedance phase, so the measured phase is treated as the AD5933 system phase. This also follows the datasheet phase measurement procedure.

Unknown RC Measurement

In measureUnknownRC(), the same frequency sweep is repeated with the unknown RC impedance connected. The code reads real and imaginary data, calculates magnitude, then uses the stored gain factor:

|Z| = 1 / (gainFactor * measuredMagnitude)

For phase, the code subtracts the stored system phase:

Zphase = measuredPhase - systemPhase

Then it projects the impedance magnitude into resistance and reactance:

R = |Z| * cos(Zphase)
X = |Z| * sin(Zphase)

This matches the datasheet warning that AD5933 real and imaginary registers are not directly the resistance and reactance of the unknown impedance. They are DFT output codes. Resistance and reactance must be calculated after calibration.

Inaccuracies and Risks in the Current Code

1. PGA Gain Is Now Explicitly Set to x1, but Excitation Range Is Still Implicit

The current code defines PGA choices, selects PGA_X1, and ORs that setting into the control high byte: 

#define PGA_X5 0x00   // D8 = 0
#define PGA_X1 0x01   // D8 = 1
#define PGA_GAIN PGA_X1

writeRegister(REG_CONTROL_HB, command | PGA_GAIN);

According to the datasheet control register, bit D8 selects PGA gain. This update correctly sets bit D8 to 1, so PGA gain is x1.

However, bits D10-D9 select the output excitation range. The code still leaves these bits at zero, so it selects:

  • Range 1 excitation, about 2 V p-p at 3.3 V supply
  • PGA gain x1

This is much better than the previous implicit x5 setting, but Range 1 can still saturate the receive ADC depending on the feedback resistor and measured impedance.

2. Feedback Resistor Value Is Not Documented in Code

The datasheet requires the feedback resistor to be chosen with the expected impedance range. Your code defines CALIBRATION_RESISTOR = 16000, but it does not define the actual hardware feedback resistor.

A rough receive gain check from the datasheet is:

ADC input ~= excitation voltage * RFB / ZUNKNOWN * PGA gain

If RFB = 16k, ZUNKNOWN = 16k, excitation is 2 V p-p, and PGA is now x1, the receive path is about 2 V p-p. This may be acceptable for the datasheet example condition at 3.3 V, but only if the real circuit stays inside the ADC linear range over the whole sweep.

3. Settling Time May Be Too Short

The code uses only 15 settling cycles. The datasheet explains that high-Q or slow-settling complex impedances need longer settling time before the ADC conversion starts.

4. Register Read Method Does Not Use the Datasheet Pointer Command

The datasheet read operation sets the address pointer using command 0xB0, then performs the read. The current code writes the target register address directly before reading. This may work in some Arduino examples, but it is not the exact datasheet read sequence.

5. Phase Is Not Wrapped

The code subtracts phase correctly, but it does not wrap the result into a normal range such as -PI to PI. Around the phase boundary, this can create sudden jumps and wrong calculated resistance/reactance.

6. Frequency Accuracy Depends on Real MCLK

The code assumes the internal oscillator is exactly 16.776 MHz. The datasheet treats this as a nominal clock. For better frequency accuracy, measure the actual clock or use a precise external clock.

Recommended Code Improvements

  1. Keep the explicit PGA constant and add explicit constants for excitation range and feedback resistor.
  2. Change setControl() so it writes both the selected range bits and the selected PGA bit.
  3. Choose range and PGA using the datasheet linear-region rule:
    excitation voltage * RFB / Zmin * PGA gain < ADC input limit
  4. Increase or experimentally tune settling cycles for the RC circuit.
  5. Wrap calculated impedance phase before calculating resistance and reactance.
  6. Use the datasheet address-pointer command for register reads.
  7. Recalibrate when changing feedback resistor, excitation voltage, PGA gain, or measurement range.
